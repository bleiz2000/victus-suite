## Запись от 2026-09-26 11:12 (+04)

### Что сделано
1. **Единый модуль палитры `bin/victus_palette.py`** — убрано дублирование:
   `PRESETS` (victus-kbd) и `BUILTIN` (ColorMaker) удалены, все берут `pal.BUILTIN`
   + пользовательские цвета из `config/colors.conf` (`pal.all_colors()`).
2. **Задел под TUI-пипетку/градиент** в том же модуле:
   `parse()` принимает имя | `#RRGGBB` | `#RGB` | `r,g,b` | `hsv(h,s,v)` | `hsl(h,s%,l%)`;
   функции `rgb_to_hsv`, `hsv_to_rgb`, `adjust(dh,ds,dv)`, `with_value`,
   `mix(a,b,t)`, `gradient(stops,steps)`, `hex_to_rgb`, `fmt`, `to_hex`.
3. **Исправлены фиксы:**
   - баг `hsv_token_to_rgb`: не умножалось на 255 → `hsv(330,0.5,1)` давал `(1,0,1)`;
   - `Changer` в `VICTUS_DRY_RUN=1` больше не вызывает `sudo` (иначе падал без терминала);
   - `Changer` больше не парсит вывод `ColorMaker palette` через subprocess;
   - потерянный при переносе цвет `olive` возвращён (48/48, значения не менялись);
   - строки локализации `kbd.bad_color`, `cm.bad_rgb` (ru+en) обновлены под новые форматы.

### Изменённые файлы
- `bin/victus_palette.py` — **новый** (единый источник правды + HSV/градиент)
- `bin/victus-kbd` — `PRESETS` удалён, `parse_color()` → `pal.parse()`, разбор одного токена
- `bin/Changer` — `load_colors()` → `pal.all_colors()`, `run_backend()` без sudo в dry-run
- `bin/ColorMaker` — `BUILTIN`/`NAME_RE` → из `pal`, `load()`/`parse_rgb()` через `pal`
- `locales/ru.json`, `locales/en.json` — форматы ошибок

### Костыли / нюансы / ошибки
- **Поведение изменилось:** `victus-kbd purple` теперь `(128,0,128)` (каноничный purple),
  раньше было `(255,0,255)` — это доступно как `magenta`. Пользователь предупреждён.
- `victus-kbd dump` без root падает `PermissionError` — **прежнее** поведение, не регрессия
  (dry-run не покрывает `dump`).
- `state/`, `logs/` в git не попадают (`.gitignore`) — цикл-дампы и pid-файл остаются локально.
- Промежуточный `gh auth login` в pty завис на вопросе «Authenticate Git… (Y/n)» —
  решено повторным запуском; **авторизация подтверждена пользователем**.

## Как добавлять новую запись (шаблон)

```markdown
## Запись от ГГГГ-ММ-ДД ЧЧ:ММ (+04)

### Что сделано
- пункт 1 (что именно, какая команда/функция)

### Изменённые файлы
- `путь/к/файлу` — что изменилось

### Костыли / нюансы / ошибки
- честно: что пошло не так, что сделано костылём, что не проверено

### Следующий шаг (план)
1. точное действие
2. что спросить у пользователя
```

**Правила записи:**
- одна запись = один подтверждённый пользователем шаг;
- время — местное, с таймзоной;
- «Следующий шаг» пишется так, чтобы его мог выполнить **чужой** агент;
- не удалять старые записи — они и есть история.
