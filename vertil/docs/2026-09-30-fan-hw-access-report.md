# Отчёт: доступ к системе охлаждения и управление вентиляторами

**Дата:** 2026-09-30
**Машина:** HP Victus by HP Gaming Laptop 16-r0xxx, SKU `8V421EA#ABD`, board **8BBE**, BIOS **F.26** (02/04/2025)
**Ядро:** `7.2.5-3-omarchy`, модуль `hp_wmi` (upstream, `drivers/platform/x86/hp/hp-wmi.ko`)
**Инструмент:** `vertil/tools/fan-access-probe.sh` (Phase A — read-only, Phase B — контролируемая запись)
**Ничего в существующем коде подсветки/`bin/`/`docs/` не изменялось** — добавлены только новые файлы в `vertil/`.

---

## 1. Что удалось получить без root (read-only)

| Параметр | Путь | Значение |
|---|---|---|
| Идентификатор драйвера | `/sys/class/hwmon/hwmonN/name` | `hp` |
| Реальный путь | `/sys/devices/platform/hp-wmi/hwmon/hwmon5` | драйвер `platform/drivers/hp-wmi` |
| Обороты CPU | `.../hpmon5/fan1_input` | 1800 RPM (idle) |
| Обороты GPU | `.../hpmon5/fan2_input` | 2100 RPM (idle) |
| PWM CPU | `.../hwmon5/pwm1` | 79 (0..255) |
| Режим | `.../hwmon5/pwm1_enable` | **2 = AUTO** |
| PWM GPU | `.../hwmon5/pwm2` | 92 (0..255) |
| `pwm2_enable` | — | **отсутствует** (см. §3) |
| Температуры | `hwmon7` (coretemp), `hwmon1` (acpitz), `hwmon3` (nvme), `nvidia-smi` | Package 41–46 °C |
| Профиль | `/sys/class/platform-profile/.../profile` | `low-power`, choices `low-power balanced performance` |

Все файлы `fan*_input` — `-r--r--r-- root:root` (читаются без root),
`pwm*` — `-rw-r--r-- root:root` (**запись только от root**).

**Важно:** индексы `hwmonN` плавают от загрузки к загрузке.
`docs/04-ventilyatory.md` ссылается на `hwmon7`/`hwmon8` — сейчас это `hwmon5`/`hwmon7`.
Искать нужно **по имени**: `for d in /sys/class/hwmon/hwmon*; do [ "$(cat $d/name)" = hp ] && echo $d; done`.

### Вывод по датчикам
- Чтение **RPM и температур полностью доступно** из userspace без root.
- Запись доступна, но только через root (см. §5 про способ получения прав).

## 2. Прямой доступ к EC / ACPI-WMI

| Путь | Статус | Комментарий |
|---|---|---|
| `hwmon` (`pwm*`) | **работает** | штатный, поддержан драйвером `hp_wmi` — **рекомендуемый путь** |
| ACPI WMI GUID `5FB7F034-…` / `95F24279-…` | занят | `hp_bioscfg` / `hp_wmi`; вызов `hp_wmi_perform_query()` **не экспортируется в userspace** |
| `/sys/kernel/debug/ec/ec0/io` | существует, `-rw------- root:root` | debugfs + root; `ec_sys write_support=Y` → технически запись в EC **возможна** |
| `/dev/port`, `acpi-ec` | есть | прямой I/O в порты 0x62/0x66 |
| `cooling_device0..4` (`type=Fan`, `max_state=1`) | бесполезны | ACPI-вентиляторы, только on/off, `cur_state=0` |

**Вердикт по EC:** не использовать. Смещения фанов в EC на 8BBE неизвестны,
в EC лежат тайминги/стоп-байты/счётчики (см. `docs/04` §«Резервные пути»).
Запись в EC — единственный путь, который реально может «убить» контроллер.
Все эксперименты ниже выполнены **только через sysfs `pwm*`**, EC не трогался.

## 3. Семантика, подтверждённая исходником `hp-wmi.c`

Для board `8BBE` драйвер подбирает `victus_s_board_params` →
`victus_s_fan_profile_params` (`fan_table=true`, `get_fan_speed=hp_wmi_get_fan_speed_victus_s`).
Отсюда: `hp_wmi_fan_control_supported() == true` и `hp_wmi_fan_table_supported() == true`.

```c
enum pwm_modes { PWM_MODE_MAX = 0, PWM_MODE_MANUAL = 1, PWM_MODE_AUTO = 2 };
#define HP_FAN_SPEED_AUTOMATIC 0x00
HWMON_CHANNEL_INFO(pwm, HWMON_PWM_ENABLE | HWMON_PWM_INPUT, HWMON_PWM_INPUT)
```

- **`pwm1_enable`** — общий для обоих вентиляторов: `0`=MAX, `1`=MANUAL, `2`=AUTO.
  У `pwm2` **нет собственного enable** — отдельно «включить/выключить» GPU-канал нельзя,
  но `pwm2` задаётся **независимо** от `pwm1`, пока режим = MANUAL.
- **Запись в `pwm1`/`pwm2` разрешена только при `pwm1_enable == 1`**, иначе ядро
  возвращает `-EINVAL` (проверено эмпирически, §4/B1).
- **`pwm1`/`pwm2` на чтение — это НЕ заданная точка, а отображённый фактический RPM.**
  Драйвер делает `rpm_to_pwm(measured_rpm/100)`. Заданный setpoint в sysfs не читается.
- Масштаб: `pwm ∈ [0..255]` линейно мапится в `RPM ∈ [min_rpm..max_rpm]`
  (`fixp_linear_interpolate`). **max_rpm = 58 → 5800 RPM** (выведено и подтверждено
  режимом MAX: `5800/6100` RPM).
- Запрос в EC — WMI `0x2E` (`HPWMI_VICTUS_S_FAN_SPEED_SET`), пары байт `{cpu_rpm, gpu_rpm}`,
  `0x00` = AUTOMATIC. Перед этим драйвер вызывает `0x10` (`FAN_COUNT_GET`) —
  по комментарию в исходнике он **переводит ноутбук в user-defined состояние** c таймаутом 120 с.
- Режимы MAX/MANUAL драйвер «поддерживает живыми» через `keep_alive_dwork` **каждые 90 с**
  (firmware сбрасывает режим через 120 с). В AUTO keep-alive отменяется.

## 4. Результаты живого теста (Phase B)

Состояние до теста: `enable=2, pwm1=79, pwm2=92, rpm=1800/2100, Package=41 °C`.

| # | Действие | Результат |
|---|---|---|
| B1 | `echo 200 > pwm1` при `enable=2` | **отклонено**: `printf: write error: Invalid argument` (`-EINVAL`). Guard работает, ничего не меняется |
| B2 | идемпотентная запись `pwm1_enable=2` | **OK** — sysfs пишется от root |
| B3 | `pwm1_enable=1` (MANUAL) | **OK**, `enable=1`, `pwm1` 79→74, RPM 1800/2100→1700/2000. **Скачка нет** (драйвер снапшотит текущий RPM) |
| B4 | `pwm1: 79 → 119` | write OK, readback сразу = 74 (это текущий RPM, не setpoint), через 12 c **CPU: 1700 → 2600 RPM** |
| B4b | `pwm2: 92 → 132` (через 10 с) | write OK, через 8 c **GPU: 2000 → 2700 RPM** |
| B5 | `pwm1_enable=2` (AUTO) | write OK, но … см. §5 |
| B6 | `dmesg` | **никаких** новых ошибок `hp_wmi`/`keep-alive` |

### Дополнительно проверено
- `pwm1_enable=0` (MAX): вентиляторы разгоняются до **5800 / 6100 RPM** за ~10 с → «максималка» работает мгновенно и надёжно.
- `pwm1_enable` принимает только `0|1|2`, иначе `-EINVAL`.
- Отклик обоих каналов подтверждён; `pwm2` реально управляет GPU-вентилятором.

**Вывод: управление оборотами работает полностью, оба канала, через обычный sysfs.**

## 5. ⚠️ Главная находка: переход AUTO даёт ~3,5 минуты 0 RPM

После записи `pwm1_enable=2` вентиляторы **останавливаются** и только потом возвращаются:

```
13:05:11  echo 2 > pwm1_enable          ← запись AUTO
13:05:25  rpm = 0 / 0                   ← вентиляторы встали
13:08:46  rpm = 300 / 200               ← начали возвращаться  (+3 м 35 с)
13:09:02  rpm = 1800 / 2100, pwm1=79, pwm2=92  ← полное восстановление (+3 м 51 с)
```

Воспроизведено **дважды** (B5 и повторный MAX→AUTO). Ошибок в `dmesg` нет,
`enable` корректно = 2, `pwm1=0/pwm2=0`. Температура держалась 43–46 °C (простой).

**Объяснение (по исходникам):** AUTO-путь драйвера вызывает `0x10`
(«user-defined state, 120 с timeout») и отправляет `{0x00, 0x00}`.
EC на 8BBE/BIOS F.26 после того, как канал уже был взят в управление,
толкует `{0,0}` как **целевую 0 RPM**, а не «верни firmware-кривую».
Возврат происходит по механизму «fallback state» по таймауту (в драйвере заявлено 120 с,
фактически измерено ~200–215 с + время раскрутки).

**Практический смысл: `pwm1_enable=2` — НЕ мгновенный и НЕ безопасный fail-safe.**
Это «остановить вентиляторы и подождать, пока BIOS вернёт управление».

### Что это значит для кода
- Откат при перегреве **нельзя** делать через `pwm1_enable=2`.
  Fail-safe = **`pwm1_enable=0` (MAX)** — работает мгновенно, проверено: 5800 RPM.
- Если AUTO всё же используется (например, при выходе), его **обязательно нужно
  верифицировать**: опрашивать `fan1_input/fan2_input`; если через ~150 с RPM всё ещё 0 —
  переключаться на MAX и логировать.
- Никогда не писать `pwm*`, пока `pwm1_enable != 1` (это `-EINVAL`, безвредно, но и бесполезно).
- Режим MANUAL подтверждён как стабильный: keep-alive драйвера сам продлевает его каждые 90 с.

## 6. Права доступа

Запись в `pwm*` — только root (`0644 root:root`). В системе уже действует шаблон проекта:
`sudoers` → `(root) NOPASSWD: /home/bl/Work/victus-suite/bin/victus-kbd`
(только для подсветки, **этот файл не трогали**).

Базовый вариант для фан-хелпера — тот же приём: отдельный узкий NOPASSWD-скрипт
(например `vertil/tools/fan-ctl`) с белым списком аргументов `0|1|2` и `0..255`,
а не широкий `sudo` для демона. Альтернатива — udev-rule, разрешающая запись
группе `hwmon`/`video` в конкретные `pwm*` (читать можно и без root).

**Реализовано в этой ревизии:** вместо нового правила использовано уже
выданное — подкоманда `victus-kbd fans …` (`bin/victus-kbd` → `fanctl.py`).
NOPASSWD-правило не имеет ограничения на аргументы, поэтому
`sudo -n …/bin/victus-kbd fans set-pwm 171 180` проходит **без пароля**
(проверено: rc=0), а белый список аргументов держит `fanctl`.
`vertil_core.probe_access()` теперь зовёт именно эту команду и возвращает
`sudo`, а не `need-password`.

## 7. Предлагаемый базовый механизм управления

**Источник истины — sysfs `hp` hwmon, никакого EC.**

```
1. Найти хендл по имени:   /sys/class/hwmon/hwmon*/name == "hp"
2. Датчики кривой:          coretemp temp1_input (+ temp*_label), acpitz, nvme,
                            nvidia-smi, fan1_input/fan2_input  (все read-only, без root)
3. Переход в ручной режим:  echo 1 > pwm1_enable        # RPM не прыгает (драйвер снапшотит)
4. Задать скорость:         echo <0..255> > pwm1         # только при enable==1
                            echo <0..255> > pwm2         # 10-секундный stagger между каналами
5. Держать живым:           драйвер сам всё делает каждые 90 с (keep_alive) — watcher не нужен
6. Fail-safe:               при temp > порога → echo 0 > pwm1_enable   (MAX, мгновенно)
                            и только проверенный, верифицированный AUTO — см. §5
7. Никогда:                 запись в /sys/kernel/debug/ec/*, /dev/port,
                            прямые WMI-вызовы, изменение кода подсветки
```

**Ограничения (зафиксировать в дизайне):**
- `pwm2_enable` отсутствует → CPU и GPU переключаются режимом **вместе**, разные значения задаются только через `pwm1`/`pwm2`.
- Setpoint из sysfs не читается — хранить его демону самому.
- `pwm_max` соответствует 5800 RPM; `min_rpm` берётся из fan-table при загрузке драйвера.
- AUTO-канал ненадёжен на данной ревизии (§5) → ручной режим + MAX-fail-safe.
- Запись во время сна/пробуждения — race с firmware; на suspend писать нельзя.

## 8. Воспроизводимость

```bash
vertil/tools/fan-access-probe.sh            # Phase A, без root
sudo vertil/tools/fan-access-probe.sh       # Phase A + B (контролируемый тест)
```

Скрипт сохраняет состояние, повышает PWM **только в сторону охлаждения**,
ставит 10-секундный stagger и принудительно возвращает `pwm1_enable=2`
через `trap` на `EXIT/INT/TERM`.

> **Итог:** прямого, штатного и полностью работоспособного канала управления
> вентиляторами два — чтение через `hwmon` (без root) и запись `pwm*` (root).
> Прямая запись в EC не нужна и не рекомендуется.
> Единственное критичное ограничение — гонка «AUTO ⇒ 0 RPM ≈ 3,5 мин»,
> обходится режимом MAX как fail-safe и верификацией RPM.
