# Отчёт: трёхфазное тестирование вентиляторов HP Victus 16-r0xxx

**Дата:** 2026-09-30 · **Устройство:** HP Victus 16-r0xxx, board 8BBE, BIOS F.26, ядро 7.2.5-3-omarchy
**Сенсоры:** `hp` (hp-wmi) hwmon5 — fan1=CPU, fan2=GPU, pwm1/pwm2; `coretemp` hwmon7 temp1 = Tcpu;
`TCPU_PCI` thermal_zone4 = VRM-прокси; `nvidia-smi` = GPU.
**Счётчик троттлинга:** `/sys/devices/system/cpu/cpu0/thermal_throttle/package_throttle{,_total_time_ms}`

## 1. Условия

Нагрузка генерировалась `loadgen.sh` (cpuburn на CPU2-15 nice 19 ionice -c3 + CUDA gpuload на RTX 4060),
адаптируется по температуре/загрузке (режимы `full`/`light`/`yield`/`idle`).
Параллельно пользователь играл в Roblox — это даёт небольшой неровный фон, поэтому все сравнения
**нормализуются по `cpu_busy`** (средняя доля активных потоков).

| Фаза | Режим | Длительность | busy, % |
|------|-------|-------------|---------|
| P1a | BIOS AUTO, **без** инжектированной нагрузки | 300 с | 23.6 |
| P1 | BIOS AUTO (+ нагрузка) | 300 с | 39.8 |
| P2 | «Топор» bang-bang, 100% при CPU≥82 / GPU≥78 | 360 с | 45.2 |
| P3 | SMART предиктивный | 480 с | 46.1 |

### Естественный эксперимент: 0 RPM vs 3900 RPM (finalize_auto_restore.log)

В момент возврата в AUTO нагрузка `loadgen` уже была остановлена, остался только Roblox
(нагрузка одинакова с обеих сторон границы):

* t=10…210 с — **0/0 RPM**, Tcpu = 92…99 °C (среднее ≈ 95.3)
* t=220…230 с — вентиляторы стартовали (300→1600→3900/4200)
* t=240…280 с — 3900/4200 RPM, Tcpu = 72…86 °C (среднее ≈ 77.4)

**Δ ≈ 18 °C** за ~45 с при одинаковой нагрузке. Перевод `enable=1 → 2` (MANUAL→AUTO)
неявно отключает вентиляторы на **215 с** (тут 205 с фактического 0 RPM, раньше воспроизводилось 3 мин 35 с).

## 3. Выводы

1. **CPU в тяжёлой нагрузке НЕ лимитируется вентиляторами в диапазоне 3900→5800 RPM.**
   P1 (3912 RPM) → 95.6 °C, P2 (5773 RPM, +48 % оборотов) → 95.4 °C. **Δ = 0.2 °C** при +48 % шума.
   «Топор» на CPU стороне даёт ~0 пользы.
2. **GPU лимитируется вентиляторами:** 4200 → 5800 RPM даёт **−8.7 °C** (77.5 → 68.8).
   Асимметрия: для CPU полезен воздух до ~4000 RPM, дальше — шум; для GPU — почти линейно до максимума.
3. **0 RPM — катастрофа:** ~215 с без обдува при Tcpu 92–99 °C. Переход MANUAL→AUTO на этой плате
   **не является мгновенным fail-safe**. Fail-safe = `pwm1_enable=0` (MAX) или удерживаемый PWM.
4. **SMART (P3) — лучший по нормированной метрике:** при +16 % работы относительно P1 дал −3.9 % событий
   троттлинга в минуту и **−17 % троттлинга на единицу работы**; относительно P2 — −2.6 % / −4.5 %.
   Абсолютное время троттлинга (~22.9 с из 60 с, ≈38 %) у всех трёх режимов одинаково — ни один
   из них не лечит перенасыщение пакета теплом.
5. **SMART в этой нагрузке НЕ выиграл в шуме** (97.7 % времени на PWM≥250, как и «топор»):
   предиктивная часть упирается в то, что CPU/VRM всегда ≥93 °C → score насыщается → 255.
   Это **правильное** поведение (безопасность), но показывает, что верхний край кривой надо пересмотреть.
6. **Рекомендация по тюнингу (подтверждена данными):** ограничить CPU-вентилятор на уровне ~4200–4500 RPM
   (дальше нет теплового выигрыша), а GPU-вентилятор оставить агрессивным (до максимума).
   Ожидаемый эффект: сохранение температур P3 при шуме уровня P1 (~−34 % оборотов).
7. **VRM-датчика нет** — `TCPU_PCI` (прокси) уходит в 101–103 °C в обеих тяжёлых фазах; точный контроль
   VRM невозможен без шины EC (hp-wmi не экспортирует).

## 4. Ограничения / оговорки

* Нагрузка не идеально идентична между фазами (adaptive loadgen + параллельный Roblox);
  поэтому ключевая нормализация — по `cpu_busy`.
* `freq_avg` логировался только в P3 — сравнение частот между фазами невозможно.
* Число событий `package_throttle` — дискретные микрособытия, не линейны с потерями производительности;
  `package_throttle_total_time_ms` — более честная метрика, и она у всех трёх режимов одинакова.
* Порог срабатывания guard.sh поднят до CPU≥99 °C (≥9 с подряд) — на этой машине 96–100 °C
  под нагрузкой штатное состояние, исходный порог 96 °C непрерывно перебивал бы контроллер.

## 6. Новые находки (пульт, 2026-09-30 16:30)

Проверено при разработке `vertil/tools/fanpult.py`:

1. **Запись `pwm1_enable=2` глушит вентиляторы ДАЖЕ если режим уже AUTO.**
   Повторено: mode был 2, rpm 3900/4200 → запись 2 → 1600/2000 (5 с) → 0/0 (10 с) и далее.
   Следствие: возврат в AUTO нельзя использовать как «безопасный сброс» — всегда ~215 с без обдува.
   В пульте команда `a` теперь требует повторного подтверждения в течение 30 с.
2. **Fail-safe подтверждён:** `pwm1_enable=0` (MAX) → 5700/5900 RPM за 8 с.
   Именно им пользовались для экстренного восстановления (CPU 94 → 89 °C).
3. **PWM → RPM линейный** (установившиеся значения, ожидание ≥12 с):

   | задано PWM | 60 | 140 | 180 | 200 | 255 |
   |---|---|---|---|---|---|
   | Fan1, RPM | 1200 | 3000 | 3900 | 4400 | 5800 |
   | Fan2, RPM | 1500 | 3000 | 4100 | 4400 | 5800 |

4. **Иерционность вентиляторов ~10 с**: PWM применяется мгновенно, RPM догоняет.
   Поэтому `pwm*` на чтение (измеренный duty) отстаёт от заданного на 5–7 единиц и не годится
   как подтверждение команды — пульт отдельно показывает «задано» и «факт».
5. **Переход MANUAL→AUTO тоже даёт 0 RPM** (пункт 1), поэтому финальным состоянием теста оставлен
   MANUAL 180/188 = 3900/4100 RPM — та же рабочая точка, что держал BIOS AUTO во всех фазах.
